# Спека: Burn — следующая версия (фокус на AI, вкладка «Аналитика»)

Дата: 2026-07-11. Статус: черновик на ревью.

## 1. Цель версии

Burn перестаёт быть «статистикой всего» и становится инструментом про AI-расходы:
показывает, куда уходят токены/деньги/лимиты, и советует, где переключение модели
вернуло бы заметную часть недельного лимита. GitHub и социальный слой (друзья,
лидерборд) выпиливаются как невостребованные.

Три блока изменений:
1. **Выпил**: вкладка GitHub, вкладка «Друзья»/лидерборд и вся обвязка друзей в
   настройках (авторизация через GitHub OAuth остаётся — см. 2.4).
2. **Новая вкладка «Аналитика»**: карточка советника за фиксированные 30 дней
   (статистика + утечки + советы + шпаргалка моделей).
3. **Актуальные прайсы**: gpt-5.6-sol/terra/luna, gpt-5.3-codex-spark и др., чтобы
   виджет и попап показывали реальную стоимость всех живых моделей.

Методика аналитики проверена экспериментом 2026-07-11 (см. память проекта
`model-switch-advisor`): парсинг транскриптов обоих агентов, лестницы моделей,
эвристика + судейские коэффициенты, лимиты Codex из rate_limits.

## 2. Продуктовое поведение

### 2.1 Попап (dropdown)

Floating island внизу переключает **две** вкладки (вместо трёх категорий):

| Вкладка | Содержимое | Периоды |
|---|---|---|
| «Расходы» | текущая AI-вкладка: сумма, дельта, топ моделей, разбивка по источникам, спарклайн | День / Неделя / Месяц (как сейчас) |
| «Аналитика» | карточка советника | фиксированно последние 30 дней, переключателя периода нет |

`DropdownSection` сокращается до `{ .expenses, .analytics }` (сейчас `ai/github/leaderboard`).

### 2.2 Карточка «Аналитика»

Блоки сверху вниз (макет проверен в эксперименте):

1. **Заголовок**: «За последние 30 дней» + диапазон дат (`11.06 — 11.07`).
2. **По источнику** (Codex, Claude Code): потрачено токенов и $, для Codex — средний
   % недельного лимита в неделю (из rate_limits роллаутов); строка «Утекает ≈N% объёма =
   $X/мес ≈ Y п.п. недельного лимита» (для Claude — «% объёма», п.п. лимита недоступны
   локально). **«% объёма» везде считается в долларах**: `Σ exp_saved / Σ cost_usd`
   источника, не в токенах.
3. **«Главные утечки и что делать»**: топ-3 кластера с оценкой $/мес и советом
   (см. 5.5 — типы кластеров и тексты советов).
4. **Шпаргалка «какую модель когда»**: Codex — описания моделей из
   `~/.codex/models_cache.json` (живые, обновляются вместе с Codex);
   Claude — статическая таблица (haiku — поиск/простые правки; sonnet — основная
   работа; opus — архитектура/глубокое ревью/сложный дебаг; fable — только
   самые тяжёлые long-horizon задачи).

Источник не найден (нет `~/.codex/sessions` или `~/.claude/projects`) — его секция
не показывается; если нет обоих, показывается состояние «нет данных» (см. 7).

### 2.3 Виджеты

- **Small**: без изменений (сумма за период + дельта).
- **Medium**: без изменений (сумма + топ моделей); строки с коммитами удаляются.
- **Large**: становится витриной советника — слева расходы + дельта + токены,
  справа топ моделей, снизу вместо лидерборда строка советника:
  «Утекает ≈$X/мес · <название топ-утечки>» (данные из последнего расчёта карточки).
  Состояния строки: расчёт ещё не выполнялся → строка скрыта; утечек нет →
  «Утечек не видно: модели подобраны по задачам.» Упоминание коммитов
  (`\(entry.commits) c`) удаляется.
- `WidgetSnapshot` теряет поля GitHub/друзей, получает поля советника
  (`leakUsdPerMonth`, `topLeakTitle`).

## 5. Подсистема «Аналитика»

### 5.1 Ингестор транскриптов

Новый модуль `StatsApp/Analytics/` (ингестор + расчёт + модели карточки).

- Источники: `~/.claude/projects/**/*.jsonl` (Claude Code), `~/.codex/sessions/**/*.jsonl` (Codex).
- Запуск: при старте приложения; далее — внутри существующего тика
  `SyncCoordinator` с гейтом «не чаще раза в час» (отдельный таймер не заводится);
  дополнительно при открытии вкладки «Аналитика», если последний ингест старше 15 минут.
- Инкрементальность: таблица `analytics_ingest_state(path, mtime, size, last_offset)`;
  файл перечитывается только при изменении mtime/size, с хвоста (`last_offset`) — jsonl
  append-only. Полный день истории парсится < 1 мин (замер эксперимента: месяц ≈ 40 с
  на Python; Swift быстрее), часовой инкремент — секунды.
- Причина срочности: retention транскриптов Claude Code ≈ 30 дней; своя БД делает
  историю постоянной.

Правила парсинга — как в эксперименте (проверены):
- Claude Code: ход = user-запись с реальным промптом (не tool_result, не isMeta,
  не sidechain) + все assistant-записи до следующего промпта; usage дедупить по
  `message.id` (одно сообщение пишется несколькими строками), брать последнее
  вхождение; `<synthetic>`-модель пропускать; cache-write разделять на 5m/1h по
  `usage.cache_creation`.
- Codex: ход = `turn_context` (model, effort); токены — дельты кумулятивного
  `token_count.total_token_usage` (`cached_input` — подмножество input); тул-коллы —
  `response_item` типов `custom_tool_call|function_call|local_shell_call`; лимиты —
  `rate_limits.used_percent` (primary 5ч / secondary неделя) при `limit_id == "codex"`.

### 5.2 Схема БД (GRDB, существующая база)

```sql
analytics_turns (
  id INTEGER PK, source TEXT, ts TEXT, day TEXT, session TEXT, project TEXT,
  model TEXT, effort TEXT, origin TEXT,           -- human | auto, см. правило ниже
  prompt_head TEXT, prompt_chars INT,             -- первые 300 символов, только локально
  n_requests INT, n_tool_calls INT, n_edits INT,
  input_tokens INT, cache_read INT, cache_create_5m INT, cache_create_1h INT,
  output_tokens INT, cost_usd REAL,
  heur_tier INT, cf_model TEXT, cf_usd REAL, exp_saved_usd REAL,
  UNIQUE(source, session, ts)
)
analytics_ingest_state (path TEXT PK, mtime REAL, size INT, last_offset INT)
analytics_rate_limits (ts TEXT, window TEXT, used_percent REAL)  -- codex 5h/week
```

Правило `origin`: промпт начинается с `<command-` → `human` (слэш-команда);
начинается с любого другого `<` (в т.ч. `<task-notification`) → `auto`; иначе `human`.
Использование: `auto`-ходы участвуют в суммах и вердиктах наравне со всеми, но
кластеризуются в спецкластер «Фоновые уведомления» (см. 5.5) и не попадают в
кластеры «болталки».

**Приватность (жёсткое правило):** `prompt_head` никогда не покидает устройство —
в `SnapshotSyncer`/aiuse-api уходят только дневные агрегаты, как сейчас. В экспорт БД
(`DatabaseExporter`) prompt_head входит (локальный файл пользователя) — допустимо.

### 5.3 Вердикты: лестницы и коэффициенты

- Классификация моделей по ступеням:
  - **T0 (frontier)**: `claude-fable-*`, `claude-mythos-*`, `claude-opus-*`,
    `gpt-5.5`, `gpt-5.6-sol`;
  - **средняя**: `claude-sonnet-*`, `gpt-5.4`, `gpt-5.6-terra`;
  - **маленькая**: `claude-haiku-*`, `gpt-5.4-mini`, `gpt-5.3-codex-spark`, `gpt-5.6-luna`.
  Вердикт «мог быть дешевле» ставится **только T0-ходам**; ходы на средних/маленьких
  моделях считаются уже оптимальными (в v1 даунгрейд среднего→маленькое не оцениваем).
- Целевые модели даунгрейда (counterfactual-ставки): claude → `sonnet-4-6` (tier 1),
  `haiku-4-5` (tier 2); codex → `gpt-5.4` (tier 1), `gpt-5.4-mini` (tier 2; в тексте
  советов упоминаются также luna/spark как равнозначные варианты — отдельной ставки нет).
- Эвристика (только T0-ходы): `n_edits==0 && n_tools==0 && out<800 && prompt<1200` → tier 2;
  `n_edits==0 && n_tools<=4 && out<4000` → tier 1; иначе tier 0.
- Ожидаемая экономия хода — одна формула (псевдокод):

  ```
  if модель не T0:      exp_saved = 0
  else if tier == 0:    exp_saved = cost_usd × judgeRatioT0(source)   // судья находит
                                                                       // даунгрейды и внутри «по делу»
  else /* tier 1|2 */:  exp_saved = max(0, cost_usd − cf_usd)          // полный counterfactual
  ```

- Судейские коэффициенты v1 — **только для страты tier 0**: claude `judgeRatioT0 = 0.057`,
  codex `judgeRatioT0 = 0.072` (откалиброваны LLM-разметкой выборки n=79, 2026-07-11).
  Хранятся константами с датой калибровки; живой LLM-судья — вне скоупа (нет API-ключа).
- Обоснование: формула повторяет прототип `experiment3.py`; коэффициенты переносят
  «знание судьи» без затрат и сети; расчёт детерминированный и пересчитываемый.

### 5.4 Лимиты Codex

- Недельный расход в п.п.: по эпохам ряда secondary.used_percent — сброс эпохи при
  падении >30 п.п. от максимума; вклад эпохи = max − первое наблюдение. Сумма
  положительных дельт запрещена (мусор из-за параллельных сессий — проверено).
- «В среднем %/нед» = сумма эпох за 30 дней / (30/7).
- Строка «≈Y п.п. недельного лимита» = доля утечки от объёма × средненедельный %.
- Для Claude Code показываем только «% объёма»; интеграция usage-эндпоинта — вне скоупа.

### 5.5 Кластеризация утечек и советы

- Ключ кластера: **источник + нормализованное начало промпта** (lowercase, первые
  60 символов) — кластеризация ведётся в разрезе источника, кластеры Codex и Claude
  не смешиваются; спецключи: `<task-notification…` → «Фоновые уведомления»,
  `<command-…` → «Слэш-команды». Тексты советов подставляются по источнику кластера.
- Кластер попадает в топ при ≥3 ходах и оценке ≥$1/мес. Сортировка: по exp_saved DESC,
  при равенстве — по числу ходов DESC, затем по ключу лексикографически. Топ-3
  (общий по обоим источникам).
- Совет по типу кластера (точные тексты):
  - роль пайплайна (промпт начинается с «Ты — »): «Зафиксируй модель этой роли в
    конфиге пайплайна: {sonnet-4-6 | gpt-5.4}»;
  - фоновые уведомления: «Фоновые уведомления обрабатывай дешёвой моделью»;
  - остальное: «Короткие вопросы — в лёгкий чат на {haiku | luna/spark}».
- Подпись кластера: «N ходов на {доминирующая по экономии модель} · ≈$X/мес».

## 6. Доменный чеклист

- **Деньги**: карточка и виджеты — целые доллары через существующий
  `MoneyFormatter.widget` (`$1 603`, NBSP-разделитель тысяч, .rounded(), не banker's);
  суммы <$1 — «<$1»; попап «Расходы» — как сейчас с центами. Экономия в месяц —
  целые доллары.
- **Проценты**: % объёма — целые («≈9%»); п.п. недельного лимита — один знак («5.9 п.п.»);
  средненедельный лимит — целые («≈64%/нед»).
- **Токены**: в карточке «Аналитика» — новый форматтер `AnalyticsFormat.tokens`
  («1.92 млрд ток» — млрд с двумя знаками, млн — целые). Существующий
  `DropdownFormat.tokens` («%.1fM»/«%.0fk») **не меняется** — вкладка «Расходы» и
  Small/Medium виджеты выглядят как сейчас.
- **Списки**: утечки — сортировка/tie-break из 5.5; шпаргалка Codex — в порядке
  `models_cache.json` (поле priority), Claude — фиксированный порядок haiku→sonnet→opus→fable.
- **Пользовательский ввод**: в новой фиче полей ввода нет — ось не применяется.
- **Float-инвариант**: cost хранится в Double USD; сравнения порогов — в целых центах
  (`Int(round(usd*100))`); суммирование — по Double, отображение только через форматтеры.
- **Тексты состояний** (дословно):
  - нет данных вообще: «Пока нечего анализировать. Burn читает историю Claude Code
    и Codex локально — поработай с агентами несколько дней, карточка соберётся сама.»
  - данных мало (<50 ходов за 30 дней): «Мало данных для выводов — карточка появится,
    когда наберётся история.»
  - утечек нет: «Утечек не видно: модели подобраны по задачам.»
  - лимит Codex недоступен (нет rate_limits): строка лимита не показывается, без текста.
  - ингест идёт первый раз: спиннер + «Разбираю историю за 30 дней…»

## 7. Миграции и совместимость

- GRDB-миграция: создание трёх analytics-таблиц; удаление данных GitHub/друзей
  не требуется (таблицы остаются мёртвыми — чистка в следующем мажоре, чтобы
  экспорт/импорт старых БД не ломался; `DatabaseValidator` не должен требовать
  удалённые сущности).
- `Config`: ключи `github_token/github_login` остаются (авторизация); использование
  токена GitHub-статистикой исчезает вместе с `GitHubFetcher`.
- Снапшот-синк и серверная схема aiuse-api не меняются.
- Виджет: `WidgetSnapshot` меняет схему. Механизма версий у снапшота сейчас нет —
  вводится поле `schemaVersion: Int` (= 2). Если `snapshot.json` на диске не
  декодируется или `schemaVersion` отсутствует/меньше 2, виджет показывает
  placeholder «Открой Burn, чтобы обновить данные» до первой записи нового
  снапшота приложением.

## 9. Критерии приёмки

1. В попапе две вкладки; «Расходы» ведут себя как текущая AI-вкладка; «Аналитика»
   показывает карточку за 30 дней без переключателя периода.
2. Ходы за 30 дней из обоих источников попадают в `analytics_turns`; повторный ингест
   не дублирует (UNIQUE-ключ).
3. Суммы карточки (±5%) сходятся с прогоном эталонного прототипа
   `scripts/analytics-prototype/experiment3.py` на тех же данных и том же окне
